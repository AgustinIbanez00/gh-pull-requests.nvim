*gh-pr.txt*    gh-pr plugin

GH-PR is a Neovim plugin to review GitHub pull requests in-editor using the
GitHub CLI as backend.

Requirements
============

- Neovim >= 0.9 (0.10+ recommended for `vim.system` / `vim.ui.open` support)
- `gh` installed and authenticated
- inside a git repository
- `render-markdown.nvim` installed (required dependency)

Optional UI backends:

- `neo-tree.nvim` (primary)
- `telescope.nvim` (fallback)
- `codediff.nvim` (primary diff backend; session fallback available)
- `snacks.nvim` (required for interactive overview)

Architecture
============

Canonical module layout after consolidation:

- Entrypoint: `plugin/gh-pr.lua` (commands + `<Plug>` wiring only)
- Public facade: `lua/gh-pr/init.lua`
- Config/state normalization: `lua/gh-pr/config.lua`
- Command specs: `lua/gh-pr/commands.lua`
- Mapping specs: `lua/gh-pr/mappings.lua`
- Core domains: `lua/gh-pr/core/*` (overview/diff/review action modules)
- UI domains: `lua/gh-pr/ui/*` (overview panes in `ui/overview/*`)
- Optional adapters: `lua/gh-pr/integrations/*`
- Health checks: `lua/gh-pr/health.lua`

Overview API
============

Use the canonical `overview` configuration table, `:GhPrOverview` command,
and `require("gh-pr").open_overview()` facade. The overview implementation
lives under `lua/gh-pr/ui/overview/*`.

Commands
========

:GhPrOpen
    Focuses/opens the pull request UI. Uses Neo-tree source `gh_pr` when
    available, otherwise falls back to Telescope if enabled.
    Re-running `:GhPrOpen` does not toggle `gh_pr` closed.
    By default `gh_pr` only appears after an async workspace probe confirms
    that the current workspace is a git repository with a GitHub remote.

:GhPrList
    Opens Telescope query and pull request picker.

:GhPrTelescope
    Opens Telescope query and pull request picker (fallback entrypoint).

:GhPrTelescopeActions
    Opens contextual Telescope actions:
      - active Review context when available
      - otherwise active PR context
      - otherwise falls back to query/PR picker

:GhPrTelescopeReview
    Opens Telescope actions scoped to active PR Review context.

:GhPrComments [number]
    Opens the PR Review source with comments integrated for the active PR
    or provided PR number.

:GhPrStartReview [number]
    Starts review flow for active/provided PR and opens PR Review source.
    Background prefetch warms textual PR file pairs into codediff temp cache
    so later file diffs open faster.
    Notification prompt (`Notify GitHub that review started...`) is shown
    only when:
      - PR is not authored by current user
      - current user is explicitly requested reviewer on that PR
      - current user has no pending review on GitHub yet

:GhPrReviewTree
    Toggles PR Review source (`gh_pr_review`).
    PR Review source sections: Overview, Labels, Files, Reviewers,
    Commits, Checks, Security, Comments, Drafts.
    `Drafts` groups pending-review comments as `file -> thread -> draft
    comment` and opens the diff location for draft items.
    In `Commits`, `<CR>` opens the full commit diff in codediff,
    matching Overview.
    In `Checks`, `<CR>` lazy-loads annotations and expands
    `check -> file -> annotation`.
    In annotation nodes, `<CR>` opens the PR diff on the modified side at
    the annotation line and paints that check's annotations over codediff.
    `Open check details` keeps direct browser access to the original check URL.
    In `Security > Code scanning`, `<CR>` lazy-loads

:GhPrMyPr
    Opens `gh_my_pr` when the current local branch matches a PR head in the
    same GitHub repository.
    `gh_my_pr` renders the same sections and mappings as `gh_pr_review`.
    In `Files`, codediff opens the GitHub base side against the real local
    worktree file on the modified side, so the head buffer stays editable.

:GhPrMyPR
    Alias for `:GhPrMyPr`.
    `file -> alert`. In alert nodes, `<CR>` opens the PR diff on the
    modified side at the alert line and paints loaded security findings
    for that file over codediff.
    In `Security > Dependency review`, `<CR>` lazy-loads
    `manifest -> dependency -> vulnerability`. In dependency nodes
    without vulnerabilities, `<CR>` opens the manifest diff. In
    vulnerability nodes, `<CR>` opens the advisory URL.
    Security sections are fully lazy; repositories without the required
    GitHub features/permissions render `Unavailable: ...` instead of
    breaking the review tree.
    `Comments` keeps `Global` section (reviews, general comments,
    orphan threads without file path).
    In `Files`, each row has fixed right-side indicators:
      - status letter (`A`/`M`/`D`/`R`/`C`)
      - viewed check icon (instead of `VIEWED` text)
      - comment badge (`icon xN`) where `N` = total file comments
        (all states).
      - indicators render as one fixed right-side block, stable under `e`
        (auto-expand width toggle) and manual resize.
    In `Files` flat list mode (`zt`), rows show muted parent-path context:
      - `filename.ext · path/to/parent`
      - long paths are compacted from the left (`…/Carpeta2/Carpeta3`).
    In `Files`, `zt` toggles list mode (`flat`) without folder grouping.
    In `Files`, `/`, `z/`, `zs`, `ze`, `zn`, `z.`, `zu`, `zw`, `zh`,
    `zd`, and `zr` manage session-only path/status/extension/viewed/
    deleted filters.
    `Global` includes review events, general PR comments, and orphan
    threads.
    In `Files`, directory nodes show `X/Y VIEWED` in yellow when at least
    one descendant file is viewed (recursive count including subfolders).
    Marking viewed/unviewed from `gh_pr_review` does not force-focus
    the `gh_pr` panel.
    Opening `Overview` from Neo-tree reuses the existing overview session
    (same PR) and performs a silent background refresh.
    Inside `gh_pr_review`, `R` forces refresh from GitHub for active PR.
    `r` re-runs start-review flow for selected PR context.
    `ra` submit pending review as approve.
    `rc` submit pending review as comment.
    `rr` submit pending review as request changes.
    `rd` discard pending review.
    `a` opens assignees edit dialog.
    `l` opens labels multi-select edit dialog.
    `u` opens reviewers multi-select edit dialog.
    `c` publish regular PR comment (`gh pr comment`) outside pending review.
    `b` on security alert nodes opens the alert URL.
    `b` on dependency vulnerability nodes opens the advisory URL.
    `x` toggles PR Review source from current context.
    `zA` expand all review nodes.
    `za` collapse all review nodes.
    `zF` expand `Files` subtree.
    `zf` collapse `Files` subtree.
    `zt` toggle `Files` list/tree mode (persisted globally).
    `zV` expand paths that contain viewed files.
    `zv` collapse paths that contain viewed files.
    `/` filter `Files` by path substring for current session.
    `z/` clear current `Files` path filter.
    `zs` select `Files` status filter.
    `ze` filter `Files` by extension.
    `zn` toggle `Files` no-extension filter.
    `z.` toggle `Files` dotfiles-only filter.
    `zu` toggle `Files` unviewed-only filter.
    `zw` toggle `Files` viewed-only filter.
    `zh` toggle `Files` hide-viewed filter.
    `zd` toggle `Files` hide-deleted filter.
    `zr` reset all session file filters.
    `zG` expand `Comments > Global` (including subgroups).
    `zg` collapse `Comments > Global` (including subgroups).
    `:GhPrOpenCommitPatch` opens selected commit diff in codediff.

:GhPrRefresh
    Refreshes PR data in active views.

:GhPRReviewRefresh
    Forces PR Review refresh in background for the active review PR.
    Alias: `:GhPrReviewRefresh`.

:GhPrOverview
    Opens overview panes (Summary with embedded Activity, Collaboration)
    for the active pull request in a dedicated tabpage with normal windows.

:GhPrOverviewRefresh
    Refreshes the active overview panes.

:GhPrOverviewMore {section} [count]
    Loads more items in a section (`checks`, `commits`, `comments`,
    `reviews`, `threads`).

Overview buffer keymaps:
    `a` approve review
    `d` request changes
    `c` comment review
    `m` merge PR
    `k` checkout PR branch
    `R` refresh overview
    `b` open PR URL in browser
    `C` open Comments PR tree for current PR
    `q` close buffer
    `H`/`L` previous/next tab
    `1..9` jump to tab
    `<CR>` open selected row action
    `<CR>` on metadata rows edits title/description/state/draft/labels/
    reviewers/assignees/milestone contextually
    `<CR>` on `## Description` heading opens multiline composer preloaded
    with current body
    (`<C-s>` submit, `q`/`<Esc>` cancel)
    `<CR>` on description line with one markdown/http(s) link opens
    preview/open action for that link
    `<CR>` on description line with multiple links opens selector menu
    state row uses direct toggle (`open`/`closed`) with confirmation
    draft row uses direct toggle (`ready`/`draft`) with confirmation
    `<CR>` on `Commits` opens the full commit diff in codediff
    `<CR>` on `Summary > Activity` thread headers toggles the thread fold
    `gp` preview markdown link under cursor in PR description
    `gr` load more for current section tab (`Summary` loads more Activity)
    `D` open diff or secondary action for selected row
    `O` open original for selected file row
    `M` open modified for selected file row
    `,x` toggle PR Review source
    Every overview edit asks confirmation before execution and refreshes
    the overview on success.
    In multi-select edits (`labels`/`reviewers`), deselected current items
    are interpreted as removals.
    PR description is rendered as markdown in `Summary`.
    In `overview.markdown.mode = "full"`, raw markdown and fenced code
    blocks are preserved (including `diff` snippets with syntax highlight).
    In `overview.markdown.mode = "legacy"`, renderer is selected by
    `overview.markdown.provider` (`render-markdown` or `builtin`).
    With `overview.markdown.github_style = true`, Summary uses
    GitHub-like markdown structure (headings + separators).
    `overview.markdown.diff_gutter = "none"` keeps thread and fix
    diff blocks clean (no per-line numbering).
    Markdown links in description support preview via `gp` or `<CR>` on
    link lines.
    `<CR>` priority in description: heading edits body; link lines
    preview/open links.
    Link preview download is only used for GitHub attachments.
    Non-attachment links prompt `open link`/`cancel` and open in browser
    only after confirmation.
    Local attachment opening is disabled by default. Set
    `overview.markdown.link_preview_open_local = "reveal_only"` to reveal
    cached files safely, or `"system"` to opt into opening
    non-dangerous local files with the OS handler.
    URL open failures (description/check/commit URL actions) emit explicit
    error notifications with opener failure details.
    Renderable GitHub attachments open in full-screen readonly preview tab
    (`q`/`<Esc>` closes).
    Overview markdown normalizes CRLF/LF line endings to avoid `^M`
    artifacts on Windows.
    PR metadata (state/review/merge/branches/stats) is rendered globally
    in header across tabs.
    `Summary` no longer renders the old `Actions` block.
    `Summary` embeds `Activity` below PR description.
    Embedded Activity includes commit uploads and PR change events
    (labels/review requests/assignees/milestones/title/base-ref/ready-
    draft/close/reopen/merge/force-push).
    Commit events in embedded Activity can be opened with `<CR>` to view
    commit diffs.
    Threads in embedded activity render as collapsible cards with
    separators, reply indentation, and inline `diff` snippets focused on
    the commented lines.
    Open threads render expanded by default; resolved/outdated threads
    render collapsed by default.
    `<CR>` on a thread header toggles the fold.
    `D` on a thread header opens compare diff from the thread comment
    commit to the latest file version in the PR.
    If inline patch resolution fails and
    `overview.thread_fix_diff.fallback_to_buffer = true`, gh-pr opens
    legacy diff buffers as fallback.

Overview panes keymaps:
    Panes are rendered in a dedicated tabpage (two normal windows:
    Summary with embedded Activity, Collaboration).
    `a`/`d`/`c`/`m`/`k`/`b` same review/browser actions as Overview.
    `<CR>` executes the action under cursor in focused pane, or toggles
    a thread fold on embedded Activity thread headers.
    `D` opens the diff or secondary action for the selected item.
    `<CR>` on metadata rows edits PR fields contextually
    (title/description/state/draft/labels/reviewers/assignees/milestone).
    `<CR>` on `## Description` heading uses multiline composer (`<C-s>` submit,
    `q`/`<Esc>` cancel).
    `<CR>` on description link lines previews attachments or confirms
    browser open for non-attachment links (multiple links open selector).
    `gr` loads more activity events.
    `?` opens floating shortcuts help.
    `<Tab>`/`<S-Tab>` cycle panes.
    `g1`/`g3` focus Summary/Collaboration panes.
    `<C-h>`/`<C-l>` switch focus between Summary/Collaboration panes.
    `<C-w>w`/`<C-w>W` cycle panes; `<C-w>h/l` focuses
    Summary/Collaboration.
    Overview panes and gh-pr popups/composer force `nospell` without
    affecting regular file buffers.

:GhPrCheckout [number]
    Runs `gh pr checkout` for the active PR or provided number.

:GhPrOpenDiff
    Opens active file in codediff for text files when
    `diff_view.mode = "vertical"` or `"unified"` and
    `diff_view.ignore_whitespace_mode = "none"` or `"trim"` (or legacy
    `diff_view.ignore_whitespace = v:false|v:true` mapped to
    `"none"|"trim"`), or in dedicated gh-pr
    non-text preview for image/binary assets.
    gh-pr downloads base/head content directly from GitHub (no git fetch
    required for file diffs).
    If review prefetch is enabled, textual files may already be cached from
    `:GhPrStartReview` / review refresh and open without re-downloading.
    With `diff_view.pr_explorer.enabled = v:true` (default), compatible PR
    text-file opens reuse a local codediff explorer session for the active PR
    snapshot, so subsequent file switches stay local and faster.
    `vertical + none|trim` opens codediff side-by-side, `unified + none|trim`
    opens codediff inline, and `horizontal` or whitespace modes `eol` /
    `blank_lines` use gh-pr's virtual diff backend instead.
    PR explorer mode only applies to compatible textual PR files; image,
    binary, and virtual-only layouts still use the existing non-text or
    virtual fallback flows.
    Persisted/configured `ignore_whitespace_mode = "all"` is coerced to
    `"trim"` on load for backward compatibility.
    `render_whitespace` / `render_endlines` markers remain virtual-backend
    only and are unavailable in codediff buffers.
    gh-pr forces codediff temp buffers to readonly/non-modifiable
    (`nomodified`, `noswapfile`) to avoid save prompts when exiting.
    gh-pr also keeps read-only `ghpr://...` buffers `nomodified`
    (virtual fallback diffs and readonly overview preview surfaces)
    to avoid save prompts on `:qall`.
    codediff windows opened by gh-pr force `number` and
    `relativenumber` to `true`.
    Binary/image/non-renderable payloads bypass codediff fallback prompts and
    open dedicated gh-pr non-text preview buffers.
    If codediff is unavailable/fails, gh-pr prompts once per session:
      - use legacy virtual fallback backend for this session
      - or keep codediff-only mode (explicit error on diff opens)
    Set `diff_view.debug.codediff_failures = true` to emit debug
    notifications with failure reason, fallback decisions, and review
    prefetch start/result events.
    In codediff file diffs, inline comments/suggestions and diff comments panel
    are available; codediff inline/unified uses the modified side for inline
    actions.
    Line comment indicators/authors are rendered in codediff side-by-side,
    codediff inline, and gh-pr virtual unified text diffs.
    Multiline review comments mark the full range (`startLine -> line`) for
    line indicators; if a range exceeds 200 lines, gh-pr marks first 100 and
    last 100 lines.
    Single multiline comments render `💬 Lx/N` progress labels on marked lines
    (with `@user` when `line_comments.virtual_text.show_authors = true`).
    If a line has multiple comments, gh-pr renders `💬 N comments`.
    Legacy virtual backend still supports configured render modes:
    vertical split, horizontal split, or unified inline.
    Non-text preview covers image files (`png/jpg/jpeg/gif/webp/bmp/svg`) and
    generic binary assets such as archives/media/documents.
    Image files are rendered as previews in virtual buffers when
    `snacks.image` is available.
    Generic binary assets open readonly metadata/action cards with base/head
    sections when applicable.
    If configured mode is `unified` for an image file, gh-pr forces split
    layout (vertical/horizontal) for base/head preview.
    If image rendering is unavailable/unsupported, fallback behavior inside
    the same non-text flow is controlled by `diff_view.images.fallback_mode`:
      - `menu` opens a custom buffer with fallback actions
      - `metadata_only` renders metadata text diff in the current buffer
      - `auto_local` opens local cached image(s), then metadata fallback
      - `auto_github` opens GitHub compare URL, then metadata fallback
    If GitHub file content cannot be loaded, command fails with an explicit
    error (no implicit patch fallback buffer).
    Virtual fallback file content normalizes CRLF/LF/CR endings to avoid `^M` artifacts.
    Diff actions are namespaced under `<localleader>` to avoid overriding
    native Neovim default keys.
    In virtual PR buffers, `<localleader>k` opens a modal floating window with comments
    for the current line.
    Press `<localleader>R` to refresh current diff buffer from GitHub.
    Press `<localleader>?` to open a floating shortcuts help dialog for this buffer.
    Press `<localleader>q` for quick close:
      - in 2-way diff closes head/modified window and keeps base/original
      - in single-buffer views closes current buffer and opens PR Review
    Press `<localleader>Q` to close current diff view(s) and open/focus PR Review.
    Press `<localleader>C` to toggle diff comments in diff view.
    If panel open/refresh fails, gh-pr shows an explicit error notification.
    When Neo-tree is available, gh-pr opens a temporary bottom comments tree
    for the current diff file (`thread -> comment`) without showing the other
    Neo-tree source headers/tabs. Set `diff_view.comments_panel.position =
    "right"` if you prefer a side pane. Otherwise it falls back to the legacy
    bottom comments panel.
    The diff comments UI only lists comments for the current diff file and
    auto-opens lazily after diff render when the current file has comments.
    When the panel is already visible, gh-pr keeps it open, shows a muted
    "Loading comments for ..." state for the next file, and refreshes it
    without moving focus or following comment nodes automatically.
    In codediff and virtual text diff buffers, `<CR>` on a commented line
    opens the line comments popup for that line.
    Inside line/thread comment popups, `r` opens a reply composer, `R` opens
    a quoted reply composer, and `x` resolves/unresolves the selected thread.
    Replies are added to the current pending review. `e` edits the selected
    comment when it belongs to the viewer, `D` deletes it, and `+` / `-`
    open the emoji reactions picker for published comments. Draft comments
    in the current pending review support edit/delete but not reactions yet.
    Reaction summaries render emoji chips such as `👍 2*` and `❤️ 1`
    instead of raw GitHub enum names.
    The reactions picker opens as a dedicated two-row grid: quick reactions
    first, then the remaining reactions, with `h/j/k/l`, arrows,
    `<Tab>` / `<S-Tab>`, `<CR>`, `q`, and `<Esc>` support.
    On first open per diff buffer, gh-pr shows a one-time hint with close shortcuts.
    Additional virtual-buffer shortcuts (when gh-pr opens the virtual diff
    backend):
      `<localleader>R` refresh current diff from GitHub
      `<localleader>q` quick close
      `<localleader>Q` close diff view(s) and open PR Review
      `<localleader>C` toggle diff comments panel
      `<localleader>c` add inline comment at cursor (`MODIFIED`/head or `unified`)
      visual `<localleader>c` add inline comment for selected range (`v`/`V`, head or `unified`)
      `<localleader>s` add inline suggestion at cursor (`suggestion` template)
      visual `<localleader>s` add inline suggestion for selected range (`v`/`V`)
      non-text preview buffers disable `<localleader>k`, `<localleader>c`,
      `<localleader>s`, `<localleader>n`, `<localleader>p`, check
      annotation overlays, and comments-tree auto-open
      non-text preview buffers: `<localleader>io` runs default preview
      action, `<localleader>im` opens preview actions menu, `<CR>` runs the
      action under cursor in metadata cards
      for `ADDED` files, opens single MODIFIED buffer (no split/unified layout)
      in `ADDED` single mode, `<localleader>c` is allowed on any line/range
      inline comments are validated before opening composer:
      - head: only inside diff hunks
      - unified: only on added (`+`) lines
      composer: `<C-s>` submit draft, `q`/`<Esc>` cancel
      `<localleader>n` next change
      `<localleader>p` previous change
      `<localleader>f` next file
      `<localleader>F` previous file
      `<localleader>v` next reviewed file
      `<localleader>V` previous reviewed file
      file navigation always reopens full diff view using current render mode
      (`vertical`/`horizontal`/`unified`)
      `<localleader>rc` submit pending review as comment
      `<localleader>ra` submit pending review as approve
      `<localleader>rr` submit pending review as request changes
      `<localleader>rd` discard pending review
      `<localleader>rx` toggle PR Review source
      codediff-backed file diffs keep native codediff keys such as `q`, `g?`,
      `t`, `]c`, `[c`, `do`, `dp`, and `gf`; gh-pr help also lists them,
      plus `gm` when codediff moved-code alignment is enabled
      in codediff-backed file diffs, native `q` closes the codediff tab while
      `<localleader>q` remains the gh-pr quick-close action
      `t` only toggles codediff between side-by-side and inline; horizontal
      split remains a gh-pr virtual-backend mode
    Layout/whitespace shortcuts are removed from defaults
    (`diff_view.shortcuts.* = ""`) and only apply if you map them manually.
    `toggle_render_whitespace` / `toggle_render_endlines` only affect the
    virtual diff backend.

:GhPrQueriesPromptReset
    Reset the conflict-resolution choice back to "ask". The next time Neovim
    detects that queries in your Lua config differ from the persisted file, it
    will show the conflict prompt again even if "No, recordar mi elección" was
    previously chosen.

:GhPrQueriesReloadLua
    Force-adopt the queries from your current Lua config, discarding any local
    manual edits. Useful after choosing "always_local" and then changing your
    mind.

=======

Top-level mappings are exposed as <Plug> targets. Global <leader> mappings are
disabled by default.

Example user map:
  vim.keymap.set("n", "<leader>gho", "<Plug>(gh-pr-open)",
    { remap = true, silent = true, desc = "Open PR UI" })

Enable default global mappings:
  require("gh-pr").setup({ mappings = { global = { enabled = true } } })

gh_pr PR nodes     Expose only `Overview` child (no `Files` subtree)
gh_pr PR rows      Keep `#number + title` as primary text and render a
                   right-aligned metadata badge cluster (`@author`,
                   `DRAFT`, checks, `CONFLICT`, review state, approvals)
`r` (gh_pr)      Start review flow for selected PR
`ra` (gh_pr)     Approve review flow for selected PR
`rc` (gh_pr)     Comment review flow for selected PR
`rr` (gh_pr)     Request-changes review flow for selected PR
`rd` (gh_pr)     Discard pending review for selected PR
`m` (gh_pr)      Merge flow for selected PR
`k` (gh_pr)      Checkout selected PR branch
`r` prompt rule   Ask `Notify GitHub...` only for eligible reviewer flow

Neo-tree Source
===============

gh-pr exposes these Neo-tree sources:

- `gh_pr` (`lua/gh_pr.lua`)
- `gh_pr_review` (`lua/gh_pr_review.lua`)
- `gh_my_pr` (`lua/gh_my_pr.lua`)

`gh_pr` registration is lazy and auto-managed by default:

- `:GhPrOpen` focuses/shows `gh_pr` and is idempotent.
- While the workspace probe is inflight, `:GhPrOpen` queues the open and
  completes it when the probe resolves.
- Default gate is `ui.neotree_sources.pr.gate = "github_repo"`, so the
  `PR` tab stays hidden outside git workspaces with a GitHub remote.
- `gate = "git_repo"` exposes `gh_pr` for any git repository.
- `gate = "manual"` disables auto-registration and keeps explicit source
  insertion only.
- `workspace = "cwd"` is the default probe root. `buffer_repo` uses the
  current buffer path and `neotree_root` uses the active Neo-tree root when
  available.
- Registering `gh_pr` does not fetch PRs. The first fetch starts when
  Neo-tree navigates that source.
- `:GhPrReviewTree` keeps toggle behavior for `gh_pr_review`.
- `gh_my_pr` is auto-managed independently from `gh_pr`: it appears only
  when the current branch matches a PR head in the same repository.
- `gh_my_pr > Files` opens codediff with the GitHub base on one side and the
  real local worktree file on the modified side, so the head buffer remains
  editable.
- `gh_pr_review > Files` uses the same local editable head behavior when the
  active review PR belongs to the current GitHub user and the checkout is on
  that PR's head branch.

Query Placeholders
==================

`queries[*].query` supports runtime placeholders:

- `${user}`: current authenticated GitHub login.
- `${owner}`: owner of repository resolved from configured remotes.
- `${repository}`: repository name resolved from configured remotes.
- `@org`: alias for current repository owner, useful for `org:@org`.

Scope behavior:

- If query has neither `repo:` nor `org:`, gh-pr appends `repo:<owner>/<repo>`.
- If query already includes `repo:` or `org:`, gh-pr does not append `repo:`.

Examples:

- `is:open review-requested:@me org:@org`
- `is:open author:${user} org:@org`

Persistence
===========

- Queries: `stdpath("state")/gh-pr/queries.json`
- Viewed files: `stdpath("state")/gh-pr/state.json`
- Diff view prefs (`mode`, `ignore_whitespace_mode`, legacy `ignore_whitespace`, `render_whitespace`, `render_endlines`): `stdpath("state")/gh-pr/state.json`
- Image fallback default action: `stdpath("state")/gh-pr/state.json`
- PR Review Files mode (`tree/list`): `stdpath("state")/gh-pr/state.json`
- PR cache: `stdpath("state")/gh-pr/pr_cache.json`
- `setup({ diff_view = ... })` defines the default diff prefs; if
  `state.json` has `prefs.diff_view`, those persisted runtime changes override
  the Lua defaults on later sessions.
- Per-open diff overrides do not rewrite `state.json`; only the runtime diff
  actions persist updated diff prefs.
- `diff_view.shortcuts.*` remain Lua-configured/opt-in and are not read from
  or written to `state.json`.
- Cache is stored per source/repo key (`gh_pr` and `gh_pr_review`).

Query persistence and conflict resolution ~

`queries.json` (v2) stores a `meta` block alongside the query list:
  `lua_signature`   canonical fingerprint of the Lua queries at last reconcile
  `conflict_choice` `"ask"` | `"always_lua"` | `"always_local"`
  `saved_at`        epoch seconds of the last write

Reconciliation logic on startup:
1. No file → save defaults (or Lua queries) as baseline.
2. File exists, no Lua queries → local file always wins.
3. File exists, Lua queries, signatures match → local edits preserved.
4. File exists, Lua queries, signatures differ (conflict):
   - `always_lua`: silently adopt Lua, overwrite local edits.
   - `always_local`: silently keep local, update signature so only the *next*
     Lua change re-triggers the check.
   - `ask` (default): apply local while showing a `vim.ui.select` prompt asking
     which side to keep and whether to remember the choice.

Cancelling the prompt (Esc) leaves the local version applied and does not
update `conflict_choice`; the prompt reappears next session.

Use `:GhPrQueriesPromptReset` to revert a sticky "always" choice back to "ask".
Use `:GhPrQueriesReloadLua` to force-adopt the current Lua queries, discarding
any local manual edits.

v1 files (`{"queries":[...]}` with no `version` field) are migrated in-memory
on first load; the file is written in v2 on the next save.
